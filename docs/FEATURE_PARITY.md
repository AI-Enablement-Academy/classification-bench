## Report data architecture and next increments

The existing [`generate_report`][g-report] computes evaluation, joins operations, constructs case tables and embeds UI logic in one function. Preserve its private snapshot/evidence boundary, but extract deterministic analysis before adding more panels. All report and presentation views should consume the same task-generic frozen data so case IDs, totals and metric semantics stay consistent.

1. Create a versioned report-data projection from a single [runner-exclusive snapshot][g-benchmark]. Include task/input/field definitions, source and evaluation hashes, declared configuration metadata, exact run/pass identity, planned positions, selected predictions, original lifecycle status, references with explicit coverage, request/attempt receipts and measured telemetry. Use arbitrary task fields/labels. Reference-bearing projections belong only to offline evaluation/reporting.
2. Separate prediction analysis from reference scoring. Validity, cross-run equality and label flips can be calculated for unlabeled inputs. Reference metrics must count only available references and disclose that denominator beside the full planned/output denominator. Do not assign zero accuracy or perfect accuracy where the reference is missing.
3. Add pure deterministic analysis functions for per-class tables/confusion, paired prompt transitions, repeat flips, difficult cases, declared historical/fresh cohorts, all eligible agreement-policy pairs and sensitivity scenarios. Each output must include included/excluded IDs, compatibility rules, original statuses and evidence selection links. Use the existing evaluator's FN treatment for missing/invalid referenced predictions.
4. Add a stable run catalog and one URL/filter state. A run is an exact configuration/prompt/repeat/split/workflow/selected-attempt identity, not a display name. Cohorts need a declared selection rule and distinct-config denominator. Parse URL IDs defensively, restore A/B/case selections on reload/history, and reveal hidden supporting targets without changing whole-experiment totals.
5. Build report and presentation panels from that projection. Prefer small modules for case inspection, cohorts, agreement, sensitivity and presentation rather than further expanding embedded string logic. Keep the artifact self-contained/private where that is the selected output contract. Any new asset packaging must remain reproducible and hash-bound.
