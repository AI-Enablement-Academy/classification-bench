# Offline framework comparison

**Decision, 2026-09-25:** keep the project coordinator as the planned execution and accounting owner. Neither Inspect AI nor promptfoo passed the hard gates for that role in this bounded spike. Inspect is a plausible thin model adapter and log viewer; promptfoo is useful for a development matrix and local assertions. Neither showed a measured reduction in operator work once the benchmark's attempt, charge, and recovery rules were included. This decision leaves the active case-study protocol unchanged.

The comparison implements the five cases specified in the source project's [harness research](https://github.com/adambkovacs/candidate-experience-benchmark/blob/58d886a94338372b280927bf5d53eda472a84c6e/docs/HARNESS_RESEARCH.md) and applies the gates in its [harness specification](https://github.com/adambkovacs/candidate-experience-benchmark/blob/58d886a94338372b280927bf5d53eda472a84c6e/docs/HARNESS_SPEC.md). It uses ten synthetic notes in fixed P1/P2 order, a simulated 429 then success, a process exit after dispatch intent, malformed JSON, and a native choice/probability object. No model, provider, dataset, credential, or reference was used. The committed [fixture source](../experiments/framework-comparison/README.md) is synthetic. Generated requests, raw `.eval` logs, promptfoo JSON, and attempt audits remained outside the repository. The main tested artifacts are under `/private/tmp/classification-framework-spike/final-out`; the default-retry run is under `/private/tmp/classification-framework-spike/fixture-out`, and the adaptive-scheduler-disabled rerun is under `/private/tmp/classification-framework-spike/fast-out`. These temporary paths may be cleaned. A small [observed-results snapshot](../experiments/framework-comparison/observed-results.json) preserves counts, statuses, timings, and source hashes without raw logs.

## Observed behavior

| Case | Inspect AI 0.3.268 | promptfoo 0.123.1 |
| --- | --- | --- |
| Ten-record P1/P2 pair | Two one-sample evaluations accepted exact prompt bytes. The side audit matched both rendered prompts, equal ordered membership, distinct project SHA-256 request identities, and `temperature=0`, `max_tokens=256`. | Two test rows accepted the same exact prompt bytes and passed local JSON assertions. The side audit matched the project's request identities. Provider context received test variables and metadata, so references must never enter its test definition. |
| Simulated 429 then success | With `max_retries=1` and a custom `should_retry`, two calls occurred. The final `.eval` had one success sample, two model events, and one error event. One raw successful `ModelCall` was present; the failed attempt had no raw response. | Default settings made two provider calls and exported one success row. With `provider.config.maxRetries=0`, only one call occurred and the row was an error. The adaptive scheduler still delayed the remaining tests by about 60 seconds; `PROMPTFOO_DISABLE_ADAPTIVE_SCHEDULER=1` made the same no-retry fixture finish in about one second. These are observed settings for the custom provider, not a proof about every built-in provider or SDK. |
| Malformed JSON | Saved the exact malformed string `{"label":"A",}` and marked the evaluation successful because this spike supplied no scorer. A separate strict parser remains necessary to count invalid output. | `is-json` failed the row and retained the malformed response in the export. That assertion checks syntax, not the benchmark's full schema or label vocabulary. |
| Native specialist | `ModelCall` retained the native choice/probability object; the sample completion was a JSON text conversion. No actual specialist adapter was tested. | The custom provider returned an object, which remained structured in the JSON export. No actual specialist method or scoring contract was tested. |
| Exit after dispatch intent | A forced exit code 77 left one side-audit attempt and an Inspect log with status `started`, zero samples, and no model event. | A forced exit code 77 left one side-audit attempt and no result export. |

The final no-retry promptfoo run exported five rows: three passes (both paired prompts and the specialist object), one invalid JSON failure, and one 429 error. Its exit code was 100 because the two negative cases were expected. A second run with `--no-cache` dispatched all five cases again; the side audit recorded two calls per case. This confirms cache bypass for this custom provider, and it also shows that an ordinary rerun is not request-level deduplication. Promptfoo [documents disk caching by default and `--no-cache`](https://www.promptfoo.dev/docs/configuration/caching/). Inspect [documents custom ModelAPI raw-call logging](https://inspect.aisi.org.uk/extensions-model-api.html), and promptfoo [documents the full test context passed to custom providers](https://www.promptfoo.dev/docs/providers/custom-api/).

## Gate decision

Here **BLOCKING** means the evidence is insufficient to adopt a framework as this benchmark's execution owner. An untested gate is not a claim that the framework is inherently incapable of meeting it.

| Gate | Finding | Status for execution ownership |
| --- | --- | --- |
| Request fidelity and matrix identity | Exact synthetic prompt bytes and paired membership passed in both. Project IDs included condition, order, prompt, route, model, and controls. A real CLI/API adapter, output schema transmission, provider route, and visible model identity were not tested. Neither framework's own evaluation ID was used as the frozen request ID. | **BLOCKING:** real adapter fidelity and model controls remain unproven. |
| Reference isolation | Fixtures and provider variables contained no labels or references. Inspect samples had empty targets. The provider process still had ordinary filesystem access; no OS boundary or sentinel access denial was enforced. | **BLOCKING:** label absence in one fixture does not prove isolation. |
| Raw evidence and interruption recovery | Both preserved successful raw output. Inspect's successful retry log retained an error event; promptfoo's default success export did not contain the first 429 attempt. Both crash views lacked a terminal response, while the separate audit retained dispatch intent. Neither run reconciled a possibly submitted provider request. | **BLOCKING:** immutable external attempt artifacts and reconciliation remain required. |
| Scheduling and policy | Inspect's retry count was set explicitly. Promptfoo needed both `maxRetries=0` and adaptive-scheduler disablement to avoid extra dispatch and cooldown in this fixture. Neither was tested as a claim/lease authority. | **BLOCKING:** the coordinator must own admission, retry decisions, and resource locks. |
| Accounting | No billable attempt occurred. Neither test demonstrated atomic reservation, one settlement per attempt, duplicate callback idempotency, or a hold for missing usage/unknown charge. | **BLOCKING:** the shared ledger must be built and tested before live execution. |
| Invalid outcomes and denominator | Promptfoo's local syntax assertion distinguished malformed JSON; Inspect needed an external parser. Neither view alone represented the planned full denominator and strict task schema. | **BLOCKING:** use the project parser and offline scorer for reports. |
| Portability and maintenance | The fixtures reproduced offline after the packages were installed. The spike added about 120 lines of framework-specific source before verification and documentation. Inspect installed fewer dependencies; promptfoo's install and default scheduler policy added work. | **RESIDUAL:** package pins are verified, but transitive lock/license and upgrade tests are open. |

A real rate limit can carry usage or a charge even when a framework displays an error. This spike intentionally did not assign money to its simulated attempts. Its results cannot certify duplicate settlement or unknown-charge behavior. Those tests belong to the project coordinator and fake provider in the next architecture phase. The [Inspect retry documentation](https://inspect.aisi.org.uk/models-concurrency.html) and [promptfoo CLI retry/export documentation](https://www.promptfoo.dev/docs/usage/command-line/) explain why framework defaults require explicit review.

## Operator effort and next gate

This was one fixture-generation command, five Inspect case launches plus one crash launch, one promptfoo matrix launch plus one crash launch, and a verification command. The promptfoo defaults required two policy changes and a rerun; the simulated 429 first produced a roughly 60-second run. The crash cases required side-audit inspection. No framework command resolved an ambiguous submission or settled a charge. There is no comparable live project-coordinator run yet, so claiming a quantified maintenance or operator reduction would be premature.

Keep the existing standard-library planner and scorer. Build the small project-owned attempt/artifact/ledger contracts next, then test a thin Inspect adapter or promptfoo report import only if it removes a measured step without altering request IDs, retry policy, denominator, or evidence. A live adapter remains gated on the source spec's smoke, identity, accounting, and recovery tests. No framework migration is needed to finish the current case-study run.
