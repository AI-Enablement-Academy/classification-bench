# Goal for the separate implementation task

Continue the private `AI-Enablement-Academy/classification-bench` repository at `/Users/adamkovacs/Documents/codebuild/classification-bench` and deliver its first usable classification benchmark runner. Start by reading `AGENTS.md`, `README.md`, `docs/HANDOFF.md`, `docs/BENCHMARK_LESSONS.md`, `docs/ROADMAP.md`, and the existing execution, evidence, budget and isolation contracts. Inspect the current implementation and run its offline tests before changing it.

The required outcome is that an operator can define a categorical classification task, input dataset, separately stored reference labels, prompt variants, model configurations, batch size and repeat count in configuration files; preview the exact work and spending bounds; run an explicitly admitted experiment with one command; inspect its status; recover safely after interruption; and generate a local report explaining quality, repeat variation, latency, token use and cost. Routine execution must not require an LLM agent to launch, inspect or reconcile each phase.

Build on the tested offline core, SQLite coordinator, budget ledger, artifact store, verified receipts and simulated runner. First implement one supported live adapter end to end, with a small, inspectable change. OpenRouter is the proposed first adapter because it exposes model routing and reported usage in one HTTP interface; verify that choice against the existing contracts before committing to it. Add a stable adapter contract so subscription CLIs and native Choice/NLI methods can follow without changing task definitions or the scheduler. Keep capabilities and unsupported controls explicit. Do not claim an adapter is working based only on installation, a mock, or successful authentication.

Preserve the experiment protocol: exact input membership and prompt bytes, observable model/provider identity, effort and sampling controls, explicit batching, separate prompt/repeat/attempt identities, strict output parsing, and no reference labels in inference. Save bounded raw response evidence before parsing. Retain invalid, refused, failed, unknown-started and never-sent outcomes. Recovery must not replay a possibly dispatched request. Retry policy must be explicit and recorded; retries never count as new repeats. Use independent configurations concurrently under one shared spending ledger and provider limits, while preserving any declared order within each configuration.

Build a useful local report from verified saved evidence. Show denominators, per-field and exact agreement, confusion patterns, class support, paired prompt effects within each pass, repeat score ranges and record-level flips. Keep invalid-output frequency separate from classification disagreement. Explain request duration, provider generation time and pure inference time separately; unavailable measurements stay unavailable. Show input/output/reasoning/cache tokens and separate observed charges, pricing estimates, subscription costs and unresolved budget holds. Allow filtering by task, model, provider, effort, prompt, repeat and execution route; make specialist methods visible. Include a readable summary of findings and access to supporting cases. Keep public export an explicit allowlisted operation.

Use the candidate-experience project as a read-only source of lessons and regression examples. Keep its ongoing model runs, result archive, public site and spending ledgers in the original repository. Do not migrate or rerun that case study as part of this implementation. Do not copy its credentials or assume its $10 OpenRouter or $1 TypeSafe approvals apply here. This repository currently has no live spending authorization. Finish the code, offline failure tests and a concrete proposed smoke plan before asking for any new model calls, credentials or spending. If live approval is absent, complete all offline work and report the live validation gate as pending.

Use bounded parallel agents for independent implementation and review, following this repository's model-routing guidance. Reuse suitable libraries where they demonstrably reduce maintenance; the offline framework comparison is already done. Avoid a full rewrite, a hosted multi-user product, cluster infrastructure or a mandatory framework migration. Start with the candidate-experience task contract and a second small fictional task fixture to demonstrate that the implementation is generic. New real task datasets need their own definitions, reference review and execution scope.

Commit and push tested increments to the private repository. Keep the README, roadmap and implementation status accurate.
