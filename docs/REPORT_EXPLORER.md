# Local report explorer

The report also contains a Case explorer and [Findings and follow-up](FINDINGS_ANALYSIS.md). Choose exact runs and cases, compare A/B fields and states, and follow evidence links from prompt, repeat and agreement findings. Selection uses fragment parameters (`run`, `compareRun`, `case`) so private local-file URLs can retain state without a server. Pair tables disclose their selection scope and paginate all eligible results; changing only a case retains the current pair table. Cost details distinguish complete/partial USD coverage, unresolved exposure, subscription invocations and excluded synthetic values.

References are optional. Omit `--labels` for unlabeled comparison, or pass `--allow-partial-references` with an incomplete reference file. Missing references are not errors; whole-run accuracy is unavailable and known-reference subsets have separate denominators. [Working fixture checks](REPORT_ANALYSIS_CHECK.md) cover the new states. These new panels currently keep their own explicit scope; synchronized report-wide filtering and the presentation view remain pending.

The report opens with every planned configuration and prompt condition. The model-group rail has General LLM, Fine-tuned LLM, Classification / decision, and Unspecified groups. Declare one of `llm`, `fine_tuned_llm`, or `decision` as optional `model_type` on a configuration before building the plan. Omit the field for Unspecified. This is an operator-declared reporting group, not proof of architecture or training history; a decision model may itself be a fine-tuned LLM. The value is frozen into the plan and request identities, so adding it after a run creates a new plan rather than relabeling historical evidence. No group is inferred from a model name, adapter or provider. The counts show configuration-prompt conditions, including zero-count groups.

The separate adapter-category rail groups rows by declared execution adapter. It recognizes OpenRouter, native Liquid, Solar, Qwen and Clef decisions, and synthetic runs; other declared, malformed and unspecified adapters remain visible in separate groups. The requested provider for a native decision adapter comes from that adapter's explicit contract, including Cloudflare for Clef, even when no operation has completed. Both rails combine with the comparison search and selectors; Reset comparison view clears them together.

Search and the model, provider, API route, and prompt controls narrow only the comparison table. The count under that table states how many conditions are visible. Select up to two rows with their Compare checkboxes to inspect the same recorded measures side by side. Once two are selected, other checkboxes are disabled until one is cleared. Clear selections works even when filters hide both selected rows, and it leaves those filters in place. Selected rows remain visible in the comparison area if later filters hide their table rows, with an explicit notice. The comparison area uses all planned passes for each selected condition. It does not recompute scores from the visible rows or from pass filters. Cost text retains its recorded currency and coverage; compare costs only within matching units and route context.

The comparison overview plots full-denominator exact agreement against mean client request duration when measured. Each point and its visible value label link to a condition and disclose measured-request coverage. Its axes stay fixed while comparison filters hide points and labels. The plot states how many visible conditions lack measured duration and how many synthetic conditions were excluded; when none can be plotted, it displays an explicit empty state. Client request duration includes network, queueing and provider handling, so it is not pure inference time; different routes may have different timing scopes. The comparison table and whole-experiment totals still include every condition.

The pass filters below the whole-experiment summary affect pass evidence and its contents links. Native provider and requested route choices appear before any operation completes; the requested route does not establish observed serving identity. The whole-experiment totals, observed outcome denominator, and condition comparison stay fixed. Reset comparison view and Reset filters act on their respective controls. Contents and Inspect condition links reveal a filtered-out target before navigation. The header navigation remains available while scrolling and marks the current major section on link clicks, matching hash changes, and observed scroll changes. Reduced-motion settings disable smooth scrolling and transitions.

This is a private, self-contained HTML file. Supporting cases contain the task inputs and reference labels; keep generated reports local. The generator and static checks are in [report.py](../classification_bench/report.py), [report_visuals.py](../classification_bench/report_visuals.py), and [test_report_ux.py](../tests/test_report_ux.py). The [report UX checklist](REPORT_UX_CHECK.md) remains the required rendered visual and keyboard check. Source-level and DOM tests do not establish rendered layout or keyboard behavior in a browser.
