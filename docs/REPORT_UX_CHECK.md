# Check the updated report

This checklist covers the report explorer update. It makes no provider calls. Use a freshly generated report; existing saved HTML does not change when the generator changes. Offline DOM checks exercise controls but cannot establish rendered appearance, focus visibility or narrow-window layout.

Fresh private examples are `private-data/report-explorer-20261002/product/report.html` and `candidate/report.html`. Use `mixed-roster/report.html` in the same directory for category checks: it explicitly contains five unexecuted configurations and ten comparison rows across native decisions, OpenRouter, synthetic and another declared adapter. All 90 positions have no selected prediction and all measurements are unavailable. It is a UI fixture, not model-performance evidence or a runnable provider configuration.

1. In the comparison overview, find one row for each configuration and prompt. The bundled fixtures have four rows. Product first-label rows should show 3/9 exact agreement; candidate first-label rows should show 0/9. Deliberately invalid rows should retain all nine positions and show nine invalid predictions. Missing measurements must remain unavailable.
2. Try the category buttons, then the model, provider, API route and prompt selectors. Search for a configuration. The comparison count must match the visible rows. Reset comparison view must restore all four fixture rows. In a custom mixed-adapter matrix, verify that the initial view includes native, OpenRouter, synthetic and other declared adapters.
3. Sort exact agreement and duration in both directions. Missing values should stay last. Observed cost is not sortable because rows may use different units. Whole-experiment totals must remain fixed while comparison filters change.
4. Select two Compare checkboxes. Confirm the side-by-side area matches each original row's agreement numerator/denominator, missing/invalid counts, duration coverage and cost units. A third selection must not silently replace a selected row. Filter a selected row out of the table; its retained comparison must clearly disclose that it is outside the current view. Clear selections and confirm the empty comparison guidance returns.
5. Use the sticky section navigation while scrolling. Check the active-section indication, click targets and heading offsets. Content must remain readable without animation. With reduced motion enabled in the operating system, smooth scrolling and transitions must stop.
6. In the separate pass filters, select one prompt: the result count should show 6 of 12 pass sections. Select one pass: it should show 2 of 12. Comparison values and whole-experiment totals must remain fixed. Reset filters must restore all 12 passes. For incompatible options, verify an explicit no-match message.
7. Use contents links and condition links in the comparison table to reach a condition or pass. Filtered targets must be revealed before navigation.
8. Expand Full request identity and telemetry evidence. Confirm request identities, receipt hashes, tokens and costs remain available. Collapse it and confirm the measurement summary remains visible.
9. Expand Supporting cases. Confirm inputs, references, predictions and outcomes remain present.
10. Navigate using Tab and Shift-Tab. Check that the skip link, categories, selectors, selection checkboxes, resets, contents links and disclosures can be reached and that focus is visible. On a narrow window, confirm navigation wraps and tables remain readable through their scroll area.

Report the exact file, browser/version, successful steps and any failures. Source-level and automated checks do not establish rendered layout or keyboard behavior. The previously accepted report's visual result does not automatically apply to this changed UI.
